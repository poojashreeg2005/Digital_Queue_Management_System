# QueueFlow AI Prototype Machine-Learning Waiting-Time Model

**Prototype ML model trained using synthetic demonstration data.**

## Purpose

This module provides a college-project demonstration of estimated queue waiting
time. It is separate from the existing queue optimization and does not replace
the deterministic waiting-time heuristic.

## Synthetic dataset

The dataset contains 5,000 reproducible demonstration records generated by
`ml/generate_dataset.py` with seed `2026`. It is saved at
`ml/dataset/sample_queue_data.csv`.

These records are not actual campus queue observations. Waiting time is
generated from queue length, counter count, service duration, priority, peak
hours, weekend behavior, and a small random noise term.

Features:

- `queue_length_ahead`: number of people ahead
- `active_counters`: active counter count
- `estimated_workload_ahead`: sum of estimated service work ahead
- `token_priority`: normal, accessibility, urgent, or emergency
- `department_category`: synthetic department category
- `service_category`: synthetic service category
- `hour_of_arrival`: arrival hour
- `day_of_week`: weekday index
- `queue_category`: student or visitor

The target is `waiting_time_minutes`. Real start time, completion time, and
realized waiting time are not used as inputs.

## Algorithm

RandomForestRegressor combines multiple decision trees and averages their
predictions. Categorical features are converted with one-hot encoding and
numeric features pass through unchanged.

## Evaluation

The data is split into 80% training and 20% test records using seed 2026.

- MAE is average absolute prediction error in minutes.
- RMSE penalizes larger prediction errors more strongly.
- R-squared describes how much variance is explained by the model.

The model is compared with a mean-value baseline. The reported metrics describe
only synthetic demonstration data.

## Integration

`services/waiting_time.py` keeps `calculate_waiting_time()` as the heuristic.
`predict_ml_waiting_time()` loads the joblib artifact once, validates inputs,
prevents negative predictions, and returns `ML_MODEL` or
`HEURISTIC_FALLBACK`.

Set `ML_WAITING_TIME_ENABLED=false` or `app.config["ML_WAITING_TIME_ENABLED"]`
to disable ML predictions.

## Student and visitor separation

The live student integration uses `queue_category="student"` and student token
records. Visitor status continues to use `calculate_waiting_time()` and does
not combine visitor and student queues.

## Missing or invalid model

Missing artifacts, load errors, invalid inputs, or disabled ML automatically
return the existing deterministic heuristic. Application startup remains
unblocked.

## Future real training

For real deployment, collect approved queue observations such as queue depth,
counter availability, service duration, priority, arrival time, and privacy-
safe anonymized department/service categories. Record actual waiting outcome
only after service completion, never as a live input feature. Evaluate against
a held-out real period and conduct fairness and performance reviews before use.
